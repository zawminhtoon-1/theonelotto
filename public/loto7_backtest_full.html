Same architecture as Loto6's backtest.html: each method's native K=15 candidate pool is computed once per draw, walk-forward (trained on only draws strictly before each target — no lookahead; LSTM additionally trains online after each prediction, with a small 60-draw bootstrap first). Full history: EVERY real Loto7 draw (#3–#691), not a recent window — unlike Loto6's backtest.html, which caps at the last 1,000 draws for cost reasons, Loto7's much shorter history (under 700 draws total) makes a genuinely complete walk-forward affordable. The K toggle above derives K = 7/9/13/17/20/22/25/28 views live in your browser via topKNums(), the same generic cross-method-consensus trim/pad function used across this site — not a separate server-side computation per K. Default/star pick: K=20.

Ranking convention: within each K, methods are ranked by highest hit7b (7-hit + either bonus number) first, then highest hit7 (7-hit, any bonus), then hit6, then hit5, then hit4 — the same hitXb-first convention used everywhere else on this site (e.g. Loto6's hit6b→hit6→hit5), NOT average hits.

Modular Cycle (mod 37): groups training draws by target_serial % 37 — Loto7's actual 37-number pool, NOT Loto6's 43 (checked and confirmed correct across every Loto7 script on this site: predictions, this backtest, and the 100-draw multi-K variant all use LOTO7_MAX = 37 throughout).

No "Best Combo" tab here (unlike Loto6's backtest.html) — that feature is built from years of accumulated elimination/xoshiro-seed/modular-cycle combo-search infrastructure that doesn't exist for Loto7 yet.
