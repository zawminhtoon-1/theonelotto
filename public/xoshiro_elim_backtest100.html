🎯 Full Elimination Backtest — Last 100 Draws (#2030–2129)

The complete 5-pass methodology from /xoshiro_elim_2130.html, run retroactively against each real draw — did the actual winning combo survive?

This applies the #2130 elimination page's full pipeline (Base = Modular Cycle K=33 ∩ xoshiro K=38 seed #692,809 → Pass 1 = 16 methods K=19 → Pass 2 = top 1,000 worst-coverage seed_hit_random_k17 seeds K=15 → Pass 3 = xoshiro K=21 seeds 0, 1, 2 → Pass 4 = historical repeat filter → Pass 5 = Worst Combo Anti-Pick K=15) to each of the last 100 real draws, one at a time.

Strict walk-forward, no leakage: every ML-derived component (Modular Cycle, the 16 methods, the Worst Combo replica) is trained ONLY on draws strictly before the draw being tested. Pass 4's historical-repeat filter is likewise restricted to draws strictly before the target — NOT including it, unlike the #2129 page's convenience inclusion. This is a genuine blind backtest: including the target draw in its own historical set would trivially eliminate it via exact match and defeat the point.

The "Never in Base" ceiling: Base is a fixed ~28-number pool (Modular Cycle ∩ xoshiro), so by pure combinatorics only about C(28,6)/C(43,6) ≈ 6.2% of possible 6-number combos could ever be contained in it — before any elimination pass runs. Most real draws are expected to land outside Base entirely; this isn't a pipeline failure, it's a structural ceiling on the whole methodology's best-case hit rate.

Full run took 493s (8.2 min) for all 100 draws. Per-draw remaining-combo lists are not stored (100 draws × up to ~150K combos each would be far too much data) — only aggregate counts and each draw's elimination outcome.
